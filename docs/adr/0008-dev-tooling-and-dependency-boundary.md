# ADR-0008: Dev-тулінг (ruff/mypy/CI) і межа залежностей рантайму

Дата: 2026-08-19
Статус: ухвалено (уточнює ADR-0004)

## Контекст
Рефакторинг у портфоліо-репо поставив питання залежностей руба: код мали
оцінювати як зразок якості, а «тільки stdlib» (ADR-0003 §1) було виконано
занадто буквально — весь HTML збирався ручною конкатенацією рядків. ADR-0004
уже провів межу «рантайм stdlib / dev-шар може мати залежності»; лишалось
вирішити, ЩО саме додати в dev-шар і чи послабляти рантайм.

## Рішення
- **Рантайм лишається zero-dep stdlib.** Причина ADR-0003 §1 жива (NAS роками
  без нагляду). Але «занадто буквально» лікуємо НЕ додаванням Jinja, а власним
  маленьким HTML-білдером (буде на етапі презентації, окремий ADR): для
  співбесіди це сильніший сигнал — вміння спроєктувати абстракцію під
  обмеженням, а не лише підключити чужу.
- **Dev-шар професіоналізуємо** (усе за ADR-0004, на NAS не їде):
  `ruff` (форматер+лінтер), `mypy` (типи), `pytest`+`coverage`, `Makefile`
  (`make check`), GitHub Actions CI (3.10/3.12), `pre-commit`.
- **Floor тулінгу — Python 3.10** (мінімум сучасного mypy; 3.9 EOL з 10.2025).
  Код stdlib-only без нового синтаксису, тож фактично сумісний і нижче.
- Три god-модулі (`engine`, `render`, `css`) і `selftest.py` тимчасово виключені
  з ruff/mypy — переписуються/пенсіонуються на пізніших етапах; список виключень
  скорочується з кожним кроком (видимий маркер прогресу).
- homoglyph-правила ruff (RUF001-003) вимкнені: несумісні з україномовними
  коментарями (CLAUDE.md §5).

## Відкинуті альтернативи
- **Adopt Jinja2 у рантайм.** Прибрало б ручну конкатенацію, але реверсить
  обґрунтоване NAS-рішення заради естетики й дає слабший сигнал, ніж власна
  абстракція. Наратив «чиста інженерія під обмеженням» цілісніший.
- **Black + flake8 + isort окремо.** `ruff` замінює всіх трьох одним швидким
  інструментом; менше конфігів, менше залежностей.
- **Строгий mypy одразу.** На нетипізованому легасі це стіна помилок; типізацію
  нарощуємо помодульно, строгі прапори — на вже типізованих модулях.

## Наслідки
+ Зелений CI — прямий, видимий сигнал якості для рев'ювера.
+ Єдиний стиль (ruff format) і типи (mypy) роблять код зразком конвенцій.
+ `make check` = локальний гейт, ідентичний CI.
− Dev-залежності треба ставити у venv (`requirements-dev.txt`); на NAS — ні.
− Виключення god-модулів означає, що поки не весь код під гейтом; чесно
  відзначено, список тане з кожним етапом.
