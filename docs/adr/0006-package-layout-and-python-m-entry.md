# ADR-0006: Рантайм — пакет `jobradar/`; запуск через `python -m jobradar`

Дата: 2026-08-19
Статус: ухвалено (замінює ADR-0005)

## Контекст
ADR-0005 переніс код у `src/` з ПЛАСКИМИ імпортами й свідомо **відкинув** пакет
`jobradar/`: «чистіше по-пітонівськи, але суперечить ADR-0004 (пакування),
а виграшу для одноосібного інструмента на NAS нема».

Змінилася рамка. Проєкт перепризначено на **референс-репозиторій для співбесіди
(EPAM)**: кодову базу читатимуть люди й оцінюватимуть якість інженерії. У цій
рамці «виграш» від пакета вже НЕ нульовий — професійна структура пакета це
прямий сигнал якості, а `sys.path`-хак у `conftest`/`selftest` і пласкі
`import jobradar` читаються як аматорські. Водночас треба зберегти інваріант
ADR-0004: NAS-деплой = «скопіюй теку й біжи», без `pip install`.

## Рішення
- Рантайм переїхав у справжній пакет **`jobradar/`** з `__init__.py`.
  Модулі: `engine` (ядро; далі розкладеться на `core/*`), `render`, `css`,
  `server` (був `webui`), `runner`, домен (`roles`, `skills`, `candidate`,
  `stats`), інфраструктурні seam-и (`paths`, `clock` — див. ADR-0008).
- Єдина точка входу — **`python -m jobradar <команда>`** (`jobradar/__main__.py`):
  `run|check|top|stats` → `engine.main`, `serve` → `server.main`. Ядро НЕ
  імпортує сервер, тому CLI лишається легким, а шар web → core односпрямованим.
- Перейменування задля чистоти: `webui.py` → `server.py`; `profile.py` →
  `candidate.py` (ім'я `profile` тінило stdlib-модуль профайлера).
- Кваліфіковані імпорти: `from jobradar import engine, skills, …`. Тести й
  `selftest` беруть ядро як `from jobradar import engine as jobradar`, тому
  наявні монкіпатч-сідери лишаються чинними.
- `run.sh`/`webui.sh` кличуть `python -m jobradar run|serve`.

## Відкинуті альтернативи
- **Лишити `src/` + пласкі імпорти (ADR-0005).** Менший churn, але тримає
  `sys.path`-хак і слабший портфоліо-сигнал — головну мету нової рамки.
- **Пакувати через `pip install -e .` + entry-points.** Класичний шлях, але
  ламає NAS-інваріант (потрібен pip і venv на вузлі). `python -m` дає той самий
  чистий запуск БЕЗ встановлення: інтерпретатор знаходить пакет у cwd.
- **`console_scripts` замість `-m`.** Те саме заперечення — вимагає встановлення.

## Наслідки
+ Професійна структура пакета; `sys.path`-хак у `conftest` зведений до одного
  рядка (корінь на шлях), дублює `pyproject [tool.pytest] pythonpath`.
+ `python -m jobradar` — впізнаваний, чистий інтерфейс; одна точка входу замість
  двох скриптів.
+ NAS-інваріант ADR-0004 цілий: пакет НЕ встановлюється, деплой = копіювання
  теки + `python3 -m jobradar`. Перевірено: `python -m jobradar` працює з cwd.
− Великий одноразовий churn (кожен імпорт, обидва скрипти, команди в доках).
− `engine.py` (1453) і `render.py` (2118) переїхали як є — їхнє дроблення на
  `core/*` і пакет `render/` — наступні етапи рефакторингу.
