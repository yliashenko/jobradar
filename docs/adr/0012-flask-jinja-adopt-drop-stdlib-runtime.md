# ADR-0012: веб-шар на Flask + Jinja2; runtime-межу «тільки stdlib» знято

Дата: 2026-08-20
Статус: ухвалено (переглядає runtime-межу ADR-0004)

## Контекст
Домовленість №1 CLAUDE.md («тільки stdlib на runtime») і межа ADR-0004
існували заради однієї мети: тихо жити на Synology NAS роками без нагляду
й без залежностей, які ламаються після оновлення DSM. Ця єдина умова
тягла за собою цілий хвіст неконвенційних рішень: саморобний
`http.server`-бекенд, власний `el()`-білдер HTML замість шаблонів, розмітку
всередині `.py`-файлів і щільні українські «чому»-коментарі, що
компенсували низькорівневий стиль.

Проєкт став головним артефактом на співбесіду в EPAM — його читають люди,
що оцінюють інженерні конвенції, і він же стане орієнтиром при створенні
повноцінного тестового проєкту. NAS фактично відпав, тож умова, що
виправдовувала весь хвіст, зникла.

## Рішення
- **Runtime може мати залежності.** Межа ADR-0004 «усе, що їде на NAS, —
  stdlib назавжди» знята: деплою на NAS немає. Рантайм-залежності живуть у
  новому `requirements.txt` (dev-шар лишається в `requirements-dev.txt`).
- **Веб-шар — Flask + Jinja2.** Маршрути — тонкі хендлери, що збирають дані
  й віддають `render_template`; HTML — у `templates/`, стилі — у `static/`
  (скомпільований `app.css` зі SCSS), `.py` тримає лише Python.
- **Коментарі — англійські й рідкі.** Код самодокументований; коментар лише
  там, де «чому» неочевидне. UI-рядки лишаються українськими (мова продукту).
- **Тести веб-шару — через Flask test client** замість прямих викликів
  рендер-функцій і асертів на HTML-рядки.

Що НЕ змінюється: `core`/`domain`-логіка (дедуп, L0, скоринг, джерела,
pipeline), сім'я тестованості (JOBRADAR_HOME, інжектований годинник,
підмінні скорер/джерело, `data-testid`), рубрика скорингу й межі профілю,
ключ і TTL дедупу. Dev-шар на pytest (ADR-0004) лишається чинним.

## Відкинуті альтернативи
- **Лишити stdlib + `el()`-білдер.** Працює, але саме та неконвенційність,
  яку рев'ювер помічає першою; хвіст рішень несумісний із подальшим
  тестовим проєктом. Умови (NAS) для цієї межі більше немає.
- **FastAPI + Jinja2.** Async зайвий для синхронного sqlite і
  server-rendered HTML (HTMLResponse — зайвий церемоніал); до того ж
  PRODUCT.md §11 резервує FastAPI під майбутню продукт-версію — мішати
  його в особисту версію розмиває цю межу.
- **Лишити `http.server`, додати лише Jinja2.** Найменша зміна, але бекенд
  лишається саморобним `BaseHTTPRequestHandler` — рев'ювер усе одно
  спитає «чому не Flask?».

## Наслідки
+ Конвенційна, впізнавана структура: фабрика `create_app`, blueprint,
  `templates/`, `static/` — те, що очікує рев'ювер.
+ Flask знімає ручну роботу: роутинг, роздача static, `request.args.getlist`
  замість склеювання повторених query-ключів, `flask.g` замість
  thread-local `CURRENT_QUERY`.
+ Тести веб-шару стають чорноскриньковими (`client.get("/")`), ближчими до
  реальної поведінки, ніж асерти на внутрішні рядки рендера.
− Нова рантайм-залежність (Flask): «скопіюй теку й біжи» більше не діє —
  потрібен Python-рантайм із встановленими залежностями.
− Одноразовий великий рефактор: увесь `render/`-пакет і `server.py`
  переписуються, ~42 HTML-залежні тести мігрують на test client.
