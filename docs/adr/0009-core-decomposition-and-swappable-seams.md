# ADR-0009: Розбір god-модуля на core/* + config/cli/pipeline; підмінні seam-и

Дата: 2026-08-20
Статус: ухвалено

## Контекст
`engine.py` (був `jobradar.py`) — god-модуль на 1453 рядки: конфіг, БД,
санітайзер HTML, дедуп, колектори, L0, скоринг, нотифікація, журнал і всі CLI-
команди в одному файлі. `cmd_run` — 163 рядки в одній функції. Тестувалось
монкіпатчингом глобалів (`http_get`, `http_post_json`, `telegram_send`). Для
портфоліо це нечитабельно; для тестованості (вимоги #3, #4) — тендітно.

## Рішення
- Ядро розкладене по швах у пакет **`jobradar/core/`**: `http`, `text`
  (санітайзер), `db` (схема/журнал), `dedup`, `filters` (L0), `collectors/*`
  (джерела), `scoring` (L1), `notify` (Telegram), `pipeline` (оркестрація).
  Конфіг і CLI — у `config.py`/`cli.py`. `engine.py` лишився тонким сумісним
  фасадом, що ре-експортує імена для тестів (зникне, коли тести перейдуть на
  прямі імпорти).
- `cmd_run` розкладено на `pipeline.run` → `_store` (дедуп+L0+запис) і
  `_score_and_notify` — кожен крок тестується окремо.
- **Підмінне джерело (#4)**: `core.sources.build_sources(cfg)` повертає
  джерела-колбеки; кожен колектор дістає мережу через ін'єктований `http`.
  Config `sources.fixture = {enabled, path}` вмикає читання вакансій із
  JSON-файлу — e2e/тест сідить відомий набір без мережі.
- **Підмінний скорер (#3)**: `pipeline.run` кличе `scorer.score(job)`;
  `build_scorer(cfg)` дає NullScorer (вимкнено), AnthropicScorer (мережа) або
  fake з тесту. Мережа `score_job` теж ін'єктується (`http_post`).
- Нотифаєр теж ін'єктується (`run(..., notify=…)`) — тести не б'ють у Telegram.

## Відкинуті альтернативи
- **Лишити монкіпатчинг глобалів.** Працює в процесі, не працює між процесами
  (e2e-сервер), і тест чіпляється за внутрішні імена.
- **Розбити «на око» по розмірах файлів.** Шви обрані за відповідальністю
  (мережа / текст / БД / джерела / скоринг), а не щоб просто вкластися в рядки.

## Наслідки
+ ~15 фокусних модулів замість god-файлу; `pipeline.run` читається як 3 кроки.
+ Збір і оцінка детерміновано тестуються без мережі (`tests/test_pipeline.py`).
+ Шари ациклічні: web → domain → core.
− Тимчасовий фасад `engine.py` існує, поки тести не мігрують на core.* (Етап 4+).
