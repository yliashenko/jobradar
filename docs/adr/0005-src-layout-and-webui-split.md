# ADR-0005: Рантайм у src/; webui розбито на css/render/server

Дата: 2026-08-18
Статус: замінено ADR-0006 (2026-08-19) — рантайм переїхав у пакет jobradar/.
Розбиття webui на css/render/server лишається чинним і в пакеті.

## Контекст
Проєкт розрісся: у корені лежали 8 .py-модулів упереміш із config, даними,
скриптами й документами, а `webui.py` став монолітом на ~2300 рядків, де
CSS, генерація HTML і HTTP-сервер жили в одному файлі. ADR-0004 зафіксував
«runtime лишається плоским» — але це стосувалося **пакування** (жодного
`pip install -e`, жодного `__init__.py`), а не того, що всі файли мусять
лежати в корені однією купою.

## Рішення
- **Рантайм-код переїхав у `src/`.** Імпорти лишаються ПЛОСКИМИ
  (`import skills`, `import jobradar`) — `src/` стоїть у `sys.path`, код не
  пакується. Це зберігає дух ADR-0004 (просто копіюй теку на NAS, жодних
  залежностей), а не суперечить йому: уточнення, не скасування.
- **Конфіг і дані лишаються в КОРЕНІ** проєкту (`ROOT_DIR = parent(src)`):
  config.json, jobs.db, profile.json, profile.md, .lock, логи. Їх редагує
  людина й вони не в git, тому живуть поруч зі скриптами деплою, а не з
  кодом. `.lock` у корені — щоб збігався з `run.sh` (той створює `.lock` у
  своїй теці = корінь); інакше кнопка й cron тримали б різні локи.
- **`webui.py` розбито на три файли за відповідальністю:**
  - `css.py` — самі стилі (рядок CSS, який вставляє `page_shell`);
  - `render.py` — уся генерація HTML (сторінки, картки, чипи, pie, шапка);
    без побічних ефектів, лише функції, що повертають рядки;
  - `webui.py` — HTTP-сервер: `Handler`, `Server`, `main`, маршрути.
  Шари ациклічні: `css ← render ← webui`. `webui.py` робить
  `from render import *` — фасад, тому всі `render_*` лишаються доступними
  як `webui.X`, і Handler та тести звертаються до них без правок.
- **Точки входу:** `run.sh`/`webui.sh` кличуть `src/jobradar.py` і
  `src/webui.py`; `conftest.py` і `selftest.py` додають `src/` у `sys.path`.

## Відкинуті альтернативи
- Пакет `jobradar/` з `__init__.py` і кваліфікованими імпортами: чистіше
  «по-пітонівськи», але суперечить ADR-0004 найсильніше (пакування,
  складніший деплой), а виграшу для одноосібного інструмента на NAS нема.
- Лишити все пласким: користувач прямо попросив структуру; моноліт webui
  на 2300 рядків реально заважав орієнтуватися.
- Розбити webui на 6 сторінкових модулів: функції в файлі перемішані по
  шарах, тож чистий контур — це 3 файли (стилі / рендер / сервер), а не 6.

## Наслідки
+ Корінь чистий: код у src/, дані/конфіг/скрипти/докази — окремо.
+ webui розкладено: сервер (292) / рендер (1452) / стилі (589) замість
  моноліту на 2296.
+ NAS-інваріант цілий: жодного пакування, жодних залежностей, деплой =
  копіювання теки + запуск `src/…`.
− `render.py` усе ще великий (1452): подальше дроблення на сторінкові
  модулі — можливий крок, коли/якщо болітиме.
− Команди подовшали на `src/` — оновлено в CLAUDE.md §6.
